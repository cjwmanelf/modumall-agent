# 모두몰 고객응대 에이전트 — 소스 코드

고객 문의 한 줄을 받아 **분류하고 → 어드민에서 조회하고 → 상담원 업무 매뉴얼에 근거해 답하는**
에이전트입니다. 고쳐 가며 실험하기 좋게 파일을 나눠 두었습니다.

## 5분 만에 시작하기

```bash
pip install -r requirements.txt
cp .env.example .env        # 그리고 OPENAI_API_KEY 를 채우세요
set -a; . ./.env; set +a    # (Windows PowerShell: $env:OPENAI_API_KEY="sk-...")

python evaluate.py          # 두 지표를 잰다  ← 여기서 시작
python chat.py              # 직접 말 걸어 본다
```

데이터는 없으면 자동으로 받습니다.

## 이 프로젝트를 쓰는 방법

**한 군데 고치고 → `python evaluate.py` → 숫자가 어디로 움직였나 본다.** 이 한 바퀴가 전부입니다.

`evaluate.py` 는 점수만 찍지 않고 **오분류 목록과 실패 사례를 함께 출력합니다.** 점수보다 그 아래
목록이 중요합니다. 무엇을 고쳐야 할지가 거기 적혀 있습니다.

## 파일 지도 — 어디를 고치면 무엇이 움직이나

| 파일 | 무엇이 들어 있나 | 고치면 움직이는 것 |
| --- | --- | --- |
| `config.py` | 모델·임계값·동시 호출 수 | 둘 다. 가장 싸게 실험해 볼 수 있는 곳 |
| **`prompts.py`** | 라우팅 지침 · 답변 규칙 | **둘 다. 가장 크게 움직인다** |
| `router.py` | 분류 그래프 (`classify` · `gate`) | ① 의도 분류 |
| `tools.py` | 조회 도구 9개 (`search_product` 포함) | ② 답변 — 특히 `tools 미호출` |
| `context.py` | 매뉴얼 쪼개기 · 라우트별 컨텍스트 | ② 답변 — 근거가 프롬프트에 들어갔는가 |
| `answer.py` | 도구 호출 루프 (agent ↔ tools) | ② 답변 |
| `guardrail.py` | 답변 속 숫자의 출처 역추적 | ② 답변 — `forbid` |
| `agent.py` | 전체 파이프라인 그래프 | 흐름 자체 (되묻기·이관 경로) |
| `evaluate.py` | 두 지표 측정 | 채점 기준 자체를 고칠 때 |
| `chat.py` | 대화 CLI | — |

코딩 에이전트(Claude Code, Cursor 등)에 이 폴더를 열어 두고 고칠 곳을 지정해 시키면 됩니다.
**무엇을 시키든 "고치고 나서 `python evaluate.py` 로 다시 재 줘"를 붙이세요.**

## 지켜야 할 것 세 가지

**평가셋(`split == "eval"`)은 절대 프롬프트에 넣지 마세요.** 예시는 `fewshot` 40건에서만 가져옵니다.
평가 문항을 넣으면 점수는 오르지만 그 점수는 거짓말이 됩니다.

**한 번에 하나만 바꾸세요.** 둘을 동시에 바꾸면 올랐어도 뭐 때문인지 모릅니다.

**바꾼 것과 숫자를 기록하세요.** 세 번쯤 지나면 "뭐가 제일 좋았더라"를 기억으로 더듬게 됩니다.

## 알아 두면 좋은 것

**숫자는 실행마다 조금씩 다릅니다.** LLM 호출이라 그렇습니다. 큰 변화가 아니면 **두 번 재 보고**
판단하세요.

**전체 측정에 3~4분, 호출 300건쯤 듭니다.** 라우팅만 보려면 `--only router` 를 쓰세요(1분).

**`config.py` 의 `WORKERS`** 는 동시 호출 수입니다. 요청 한도(rate limit) 오류가 나면 낮추세요.

**도구를 고쳤으면 한 번 호출시켜 보세요.** 선택 인자를 `Optional[int] = None` 이 아니라
`int = None` 으로 적으면 모델이 `None` 을 보냈을 때 스키마 검증에 걸려 왕복이 낭비됩니다.
`python chat.py "캔버스화 배송비 얼마예요?"` 로 도구가 제대로 불리는지 바로 확인할 수 있습니다.
